# AI 사주·운세 개인 분석 서비스 개발 계획서 (Development Plan)

## 1. 개요 및 목표

본 문서는 [`PRD.md`](file:///c:/zip/PRD.md)에 기반하여 **AI 사주·운세 개인 분석 서비스**를 성공적으로 구현하기 위한 기술 아키텍처 및 세부 실행 계획서입니다.

### 1.1 프로젝트 목표
- **간편한 운세 경험**: 생년월일과 태어난 시간(또는 모름) 입력만으로 띠, 별자리, 사주 요소를 결합한 개인 성향 및 오늘의 운세를 즉시 확인.
- **단일 화면(Single Page) 완결형 인터랙션**: 페이지 전환, 회원가입, 결제 없이 단일 뷰에서 전 과정 수행.
- **Zero-DB 프라이버시 우선 설계**: 사용자 개인정보 및 운세 결과를 서버 DB에 저장하지 않는 완전한 무상태(Stateless) 구조.
- **10초 이내 결과 반환**: 빠르고 안정적인 AI/사주 분석 파이프라인 구축.

## 2. 아키텍처 및 기술 스택

### 2.1 기술 스택 (Tech Stack)
- **Framework**: Next.js 16 (App Router, React 19, Server Actions / Route Handlers)
- **Styling**: Tailwind CSS v4, OKLCH 테마 시스템, Lucide Icons, tw-animate-css
- **Language**: TypeScript (엄격한 타입 안전성 보장)
- **AI & Analysis Engine**: Next.js Route Handler (`/api/fortune`) + LLM Provider (Google Gemini / OpenAI) + 사주/천간지지/별자리 결정 알고리즘
- **Data Sharing**: Base64URL / LZ-String 기반 URL 직렬화/역직렬화 (DB 없는 공유 시스템)
- **Validation**: Zod (AI 응답 스키마 및 입력 데이터 무결성 검증)

### 2.2 시스템 구조도 (Data Flow)

```
[ 사용자 브라우저 (단일 화면) ]
   │
   ├── 1. 생년정보 입력 및 클라이언트 유효성 검증 (E-01~E-06, E-14)
   │
   ├── 2. 분석 요청 POST /api/fortune (Debounce, AbortController, E-07)
   │        │
   │        ▼
   │   [ Next.js API Route Handler ]
   │        ├── A. 천간지지/띠/별자리 계산 모듈 (lib/saju-calculator.ts)
   │        ├── B. AI 프롬프트 생성 및 LLM 호출 (10초 타임아웃, E-08)
   │        └── C. Zod 스키마 검증 & 후처리 (E-11~E-13 강제 보정)
   │        │
   │        ▼
   ├── 3. 결과 렌더링 (Hero 카드, 성향 3종, 상세 3종, 총평, 오늘의 운세)

            ├── Fallback 1: 인코딩된 URL 클립보드 복사
            └── Fallback 2: 텍스트 요약본 복사 (E-16, E-17)
```

## 3. 핵심 설계 원칙 및 아키텍처 결정

### 3.1 단일 화면 상태 머신 (Single Page State Machine)
화면은 별도의 라우트 분기 없이 4가지 상호 배타적 상태로 관리됩니다.

```
[ IDLE ] ──(제출/검증)──> [ LOADING ] ──(성공)──> [ DONE ]
   ▲                            │                     │
   │                            └──(실패)──> [ FAILED ]│
   │                                           │      │
   └──────────────(입력값 변경 / 초기화)──────────┴──────┘
```

- **IDLE**: 입력 폼 활성화, 결과 영역 숨김.
- **LOADING**: 버튼 비활성화, 스피너 및 '운세를 분석하고 있어요...' 메시지, 중복 요청 차단.
- **DONE**: 폼 하단으로 부드러운 스크롤, 결과 카드 및 공유하기 버튼 표시.
- **FAILED**: 입력값 유지, 분석 버튼 재활성화, 오류 메시지 및 재시도 버튼 노출.

### 3.2 입력값 변경 시 결과 무효화 (E-14 대응)
- 분석 완료(`DONE`) 상태에서 사용자가 연/월/일/시/시간모름을 변경하는 즉시 상태를 `IDLE`로 전환하고 기존 결과 카드를 화면에서 안전하게 제거하여 잘못된 결과 오인을 방지합니다.

### 3.3 Zero-Database 공유 엔진 (DB-less Share Engine)
- PRD 1.3 및 4.2 명세에 따라 DB를 일절 사용하지 않습니다.
- 분석 결과의 핵심 메타데이터(타입, 성향, 별점, 생년월일 등)를 직렬화하여 URL Hash 또는 Query Param(`?data=...`)으로 인코딩합니다.
- 공유 URL로 진입 시 단일 화면에서 해당 데이터를 즉시 역직렬화하여 결과 카드를 즉시 복원합니다.

### 3.4 엄격한 AI 스키마 검증 및 보정 (E-11 ~ E-13 대응)
- AI 응답이 불안정하거나 필드가 누락될 경우를 대비해 Zod 파서를 적용합니다.
- 핵심 성향 개수(정확히 3개) 및 운세 점수(정수 1~5점)를 자동 clamp 및 fallback 처리하여 UI 크래시를 원천 차단합니다.

## 5. 범위 제한 (Out of Scope - PRD 6 준수)

본 프로젝트는 5시간 MVP 집중 개발 원칙을 준수하며 아래 항목은 개발 범위에서 제외합니다.
- ❌ 회원가입 / 로그인 시스템
- ❌ 결제 / 유료 결제 모듈
- ❌ 사용자 정보 및 결과 영구 저장을 위한 DB (MySQL, PostgreSQL, MongoDB 등)
- ❌ 궁합 (타인과의 사주 비교) 기능
- ❌ 주간 / 월간 / 연간 운세
- ❌ AI 실시간 멀티턴 채팅 기능
