# Astra Destiny 랜딩페이지 구축 계획

작성일: 2026-08-27  
상태: 구현 계획 수립 완료

## 1. 목표와 원칙

`design.md`의 Astra Destiny 방향(고대의 지혜와 디지털 영혼)을 첫 화면에서 전달하고, 방문자가 짧은 설명만으로 서비스 가치를 이해한 뒤 사주 분석을 시작하도록 만드는 단일 랜딩페이지를 구축합니다.

- 톤: 신비롭지만 과장되지 않은 현대적 AI 서비스
- 시각 언어: 라이트 테마, 시그니처 퍼플 `#6b38d4`, 투명한 글래스 카드, soft shadow, 넉넉한 여백
- 핵심 전환: `무료로 내 운세 분석하기` CTA → 기존 생년월일 입력/분석 흐름
- 보존 원칙: 사주 계산·Gemini 응답·공유 URL·PRD E-01~E-17 동작은 변경하지 않음

## 2. 페이지 구조

### L-1. 상단 네비게이션

- 로고(Astra Destiny)와 단일 핵심 CTA만 배치
- 메뉴를 늘리지 않아 분석 시작이라는 목표에 집중
- 스크롤 시에도 CTA 접근성을 유지할지 명세에 따라 결정

### L-2. 히어로 섹션

- 메시지: “나의 오늘을 읽는 가장 지적인 방법”과 같은 짧고 명확한 가치 제안
- 보조 문구: 전통 사주와 AI 분석을 결합한다는 설명
- Primary CTA와 보조 링크(분석 방식/서비스 안내) 제공
- 오로라·별빛·반투명 카드로 신비로운 분위기를 만들되 텍스트 대비를 우선

### L-3. 신뢰와 작동 방식

- 3단계 플로우: 생년월일 입력 → AI 사주 분석 → 오늘의 실천 확인
- “결정론적 예언이 아닌 자기이해를 위한 콘텐츠”라는 기대치 안내
- 실제 사용자 개인정보를 노출하지 않는 예시 결과 카드 사용

### L-4. 기능/결과 미리보기

- 성향 요약, 세부 분석, 오늘의 운세, 작은 실천 등 핵심 결과를 카드로 미리 보여줌
- 글래스모피즘은 카드 내부에 제한적으로 사용하고 모바일에서는 불투명 fallback 적용
- 결과 화면으로 이어지는 CTA를 섹션 하단에 반복 배치

### L-5. 안전성·FAQ·최종 CTA

- AI 생성 결과, 의료·법률·금융 조언 아님, 공유 URL 동작을 짧게 설명
- 개인정보 저장 여부와 분석 소요 시간을 FAQ로 안내
- 마지막 CTA와 푸터(서비스명, 면책, 공유/접근성 안내) 구성

## 3. 구현 스프린트

### LP-1. 콘텐츠·전환 설계

- 히어로 헤드라인, CTA, 섹션 카피, FAQ를 한국어 용어집으로 확정
- 랜딩 CTA가 기존 입력 폼을 열거나 해당 위치로 이동하는 방식 결정
- 이벤트 명세: hero CTA, section CTA, 분석 시작, 공유 클릭

### LP-2. 디자인 토큰과 레이아웃 기반

- `app/globals.css`에 `design.md` 색상·간격·radius·shadow·glass 토큰 반영
- `app/layout.tsx`의 Noto Sans KR을 기본 서체로 사용하고 헤드라인 위계를 정의
- 최대 콘텐츠 폭, 섹션 간 여백, 모바일 breakpoint를 정함

### LP-3. 섹션 컴포넌트 구현

- `landing-nav`, `landing-hero`, `how-it-works`, `result-preview`, `trust-faq`, `landing-footer` 컴포넌트 구성
- 반복 CTA는 공통 버튼 컴포넌트를 사용해 상태·포커스·로딩 표현을 통일
- 기존 분석 UI와 스타일 토큰을 공유하되 기능 컴포넌트와 콘텐츠 컴포넌트를 분리

### LP-4. 인터랙션·반응형·접근성

- 부드러운 진입 모션, hover/focus, 스크롤 이동을 적용하되 `prefers-reduced-motion` 지원
- 360/390/480/768/1024px에서 오버플로·줄바꿈·CTA 터치 영역(최소 44px) 확인
- 시맨틱 heading 순서, 키보드 탐색, 포커스 링, aria-label, 명도 대비 검증

### LP-5. 검증·릴리스

- 랜딩에서 분석 시작까지 실제 흐름과 뒤로가기/새로고침 동작 확인
- `npm run test:ai`, 타입 검사, 프로덕션 빌드 실행
- Lighthouse 기준(성능·접근성·SEO) 측정 및 메타/OG 이미지 점검
- 전후 스크린샷과 전환 이벤트 결과를 기록한 뒤 Vercel Preview에서 확인하고 Production에 반영

## 4. 완료 기준

1. 첫 화면에서 서비스 가치와 핵심 CTA가 5초 이내 이해된다.
2. 모든 CTA가 기존 분석 흐름으로 정확히 연결되고 PRD 기능 회귀가 없다.
3. `design.md`의 컬러·타이포그래피·라운딩·글래스·여백 원칙이 주요 섹션에 일관되게 적용된다.
4. 모바일·데스크톱에서 레이아웃이 깨지지 않고 키보드/스크린리더 사용이 가능하다.
5. AI 테스트·타입 검사·빌드·핵심 브라우저 플로우가 통과한다.

## 5. 리스크와 대응

- 글래스 효과가 가독성을 낮출 수 있어 카드 배경 불투명도와 대비를 먼저 검증합니다.
- 랜딩을 별도 라우트로 만들 경우 기존 `/` 진입 동작과 공유 URL 호환성을 확인합니다. 기본 구현안은 `/`에 랜딩을 두고 CTA 아래에 기존 분석 흐름을 배치하는 방식입니다.
- 이미지·일러스트는 초기에는 CSS 오로라/별빛과 제품 UI 미리보기로 구성해 번들·라이선스 리스크를 줄이고, 필요 시 최적화된 자산을 추가합니다.
