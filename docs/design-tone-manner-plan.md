# 디자인 톤앤매너 전면 개편 계획

작성일: 2026-08-27  
상태: 디자인 명세 확인 완료 / 구현 착수 대기

## 1. 확인 결과와 범위

루트의 `design.md`를 확인했습니다. Astra Destiny의 핵심 방향은 **고대의 지혜와 디지털 영혼**을 결합한 신비롭고 투명한 라이트 테마이며, 키워드는 신비로움·투명함·전문성·직관성입니다.

확정된 기준은 다음과 같습니다.

- 컬러: Primary `#6b38d4`, Surface `#f8f9ff`, Surface Variant `#eff3ff`, Text Primary `#1a1a1a`, Text Secondary `#666666`
- 타이포그래피: Pretendard 또는 Noto Sans KR, 큰 굵은 헤드라인과 읽기 편한 본문 행간
- 형태: 카드·버튼 16px 이상 radius, 넉넉한 여백, 가벼운 soft shadow
- 효과: 네비게이션·입력 영역·결과 카드에 반투명 배경과 backdrop blur를 사용하는 글래스모피즘
- 컴포넌트: 단순한 Top Navigation(로고+필수 액션), 퍼플 포커스 입력, 퍼플/그라데이션 CTA

이번 개편의 범위는 사주 결과 서비스의 전체 시각 언어(색상, 타이포그래피, 여백, 모서리, 그림자, 모션, 문구 톤, 컴포넌트 상태)를 `design.md`의 단일 기준에 맞추는 것입니다. 사주 계산·AI 응답·공유 URL 등 기능 동작과 E-01~E-17 요구사항은 유지합니다.

## 2. 현재 UI 기준선

- 전역 토큰과 모션: `app/globals.css` (OKLCH 보라 계열, 크림 배경, 오로라 배경, reduced-motion 대응)
- 폰트·메타데이터: `app/layout.tsx` (Noto Sans KR + Gowun Batang)
- 사용자 흐름: `hero-section`, `birth-form`, `analyzing-card`, `result-section`, `today-fortune-card`, `share-card`, `toast-view`, `state-preview`
- 검증 대상 상태: 초기/입력 오류/분석 중/성공/실패/공유 성공·실패/모바일 반응형
- 접근성 기준선: 키보드 포커스, aria 라벨, 첫 오류 포커스, `prefers-reduced-motion`

개편 전 캡처와 테스트 결과를 기준선으로 보존해 시각 변경과 기능 회귀를 분리해서 확인합니다.

## 3. 실행 순서(스프린트)

### D-1. 명세 추출 및 디자인 토큰 (명세 확인 완료)

- 위 확정 팔레트를 CSS 변수로 정의하고 기존 OKLCH 토큰과의 변환·대비를 확인
- Noto Sans KR을 기본 서체로 확정하고 헤드라인/본문/레이블 크기와 행간을 토큰화
- 16px 이상 radius, glass surface, soft shadow, 넉넉한 spacing 토큰을 정의
- 기존 토큰과 1:1 매핑하고 상태별 대비를 정의
- `app/globals.css`, `app/layout.tsx`에 토큰·폰트·기본 배경 적용
- 산출물: 디자인 토큰 표, 명세-코드 매핑표

### D-2. 진입 화면과 입력 경험

- 히어로 헤드라인, 보조 문구, CTA의 문장 톤을 브랜드 보이스에 맞춤
- 생년월일 폼의 라벨·도움말·오류·버튼 상태를 동일한 계층 구조로 정리
- 모바일 우선 레이아웃과 터치 영역(최소 44px) 확인

### D-3. 분석·오류·피드백 상태

- 분석 중 로딩, 실패/재시도, 토스트, 빈 상태를 같은 시각 문법으로 통일
- 모션은 명세의 속도·이징을 적용하되 reduced-motion에서는 정적 상태 제공
- 오류 메시지는 불안을 키우지 않는 안내형 문구로 정비

### D-4. 결과·오늘의 운세·공유

- 결과 카드, 점수, 키워드, 오늘의 작은 실천, 공유 카드의 우선순위와 강조색 통일
- 긴 텍스트·한글 줄바꿈·공유 미리보기에서 레이아웃이 깨지지 않도록 검증
- 면책 문구와 AI 생성 결과 안내를 톤앤매너에 맞추되 의미는 보존

### D-5. 반응형·접근성·콘텐츠 QA

- 360/390/480/768/1024px 뷰포트에서 주요 상태 스냅샷 비교
- 명도 대비, 포커스 링, 키보드 순서, aria 상태, 색상만으로 전달되는 정보 여부 점검
- 제목/버튼/오류/공유 문구의 맞춤법·존댓말·용어집 일관성 점검

### D-6. 회귀 검증 및 릴리스

- `npm run test:ai`, `npx tsc --noEmit --incremental false`, `npm run build` 실행
- E-01~E-17 및 공유 URL·자동 스크롤·실패 재시도 동작 재검증
- 변경 전후 캡처와 체크리스트를 스프린트 문서에 기록하고 커밋 단위로 릴리스

## 4. 완료 기준

1. `design.md`의 모든 필수 규칙이 토큰 또는 컴포넌트 스타일에 매핑되어 누락이 없다.
2. 초기부터 결과·오류·공유까지 모든 화면의 문구와 시각 계층이 같은 브랜드 보이스를 사용한다.
3. 기능 동작과 API 계약을 변경하지 않고 기존 PRD 체크리스트를 통과한다.
4. 지정 뷰포트와 키보드/스크린리더 핵심 흐름에서 깨짐이나 대비 문제를 발견하지 못한다.
5. 테스트·타입 검사·프로덕션 빌드가 통과하고, 변경 사항과 잔여 리스크가 문서화된다.

## 5. 진행 방식과 보류 사항

- 명세 기준은 확인되었으므로 D-1 토큰 작업부터 착수한 뒤 D-2~D-6을 순차 진행합니다.
- Pretendard 도입 여부는 현재 Noto Sans KR과 렌더링·번들 비용을 비교한 후 결정합니다(기본안: Noto Sans KR 유지).
- 글래스모피즘은 텍스트 대비와 저사양 모바일 성능을 확인하며, backdrop blur 미지원 환경에는 불투명 surface를 fallback으로 제공합니다.
- 이미지/아이콘이 외부 리소스를 요구하면 라이선스와 로딩 성능을 확인한 후 적용합니다.
- 각 스프린트 종료 시 변경 파일, 테스트 결과, 다음 스프린트 진입 조건을 `docs/sprints/`에 기록합니다.
